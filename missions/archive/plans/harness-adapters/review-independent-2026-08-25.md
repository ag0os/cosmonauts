### E-1 — AC-7's premise is factually false for one of its five named targets ⊕(A:PR-001)

**Ratified text (spec AC-7):** "The repo's own stale exports (`.claude/skills/*`)
are regenerated through the new path as the first live validation."

**Reality, verified this session:**

| Target | Source bytes | Target bytes | Files in target | Classification |
|---|---:|---:|---:|---|
| `plan` | 8893 | 6888 | 1 | genuine stale export |
| `task` | 13210 | 7787 | 1 | genuine stale export |
| `roadmap` | 5289 | 4262 | 1 | genuine stale export |
| `skills-cli` | 1690 | 1687 | 1 | genuine stale export |
| **`playwright-cli`** | **2693** | **7450** | **8** | **NOT a cosmonauts export** |

`.claude/skills/playwright-cli/` is generated by a *third-party tool* —
`playwright-cli install --skills` — and the cosmonauts source
(`bundled/coding/skills/playwright-cli/SKILL.md`) is a 2.7KB wrapper whose own
body instructs the user to run that command. The target carries an
`allowed-tools: Bash(playwright-cli:*)` frontmatter key the source does not
have, plus a `references/` tree of 8 files.

B-012 would move it aside, write the 2.7KB wrapper over it, and delete the
backup — destroying richer third-party user data, which is exactly the
destructive override INV-2/AC-3 and B-007 ("there is no force overwrite path")
forbid. Following the wrapper's own instruction afterward would immediately
rewrite the managed target and make the next `--check` report `locally-edited`.

**Options for the human:**
- **(a)** Narrow AC-7's validation set to the four genuine stale exports and
  record `playwright-cli` as an explicitly excluded foreign asset.
- **(b)** Keep all five but require per-target authorization evidence
  distinguishing a stale cosmonauts copy from a foreign asset before any move.
- **(c)** Ratify a broader rule: a name collision between a cosmonauts source
  and a foreign target is a permanent conflict, never a migration candidate.

*Recommendation: (a) plus the general rule in (c).* (b) alone leaves the
same trap for the next tool that installs a same-named skill.

**Second-order fact worth ratifying:** target-side frontmatter is *not*
uniformly `{name, description}` (the spec's Assumptions section asserts
uniformity, but verified only across the 51 **source** files). The transform
seam must tolerate foreign keys on the target side.

## Confirmed defects — design revision required (derived ground, no human ruling needed)

### High

- **H-1 (A:PR-002) — pair migration self-deadlocks.** Design §7 step 2 acquires
  the personal Claude owner lock, then runs "ordinary sync" while holding it;
  Design §5 has ordinary sync acquire that same lock. `withEntityFileLock`
  (`lib/entity-file-lock.ts:64-76`) exposes no lock token and no lock-held entry
  point; on re-acquisition `acquireEntityFileLock` finds the lock file, calls
  `isProcessAlive(existing.pid)` — **which is this very process** — never
  reclaims, and falls into bounded backoff that is unbounded by default.
  Implemented literally, B-008 hangs *after* moving both live commands to backup.
  Needs an explicit lock-held materialization seam or a single non-reacquiring
  transaction.

### Major

- **M-1 (B:design-attack, CONFIRMED) — cross-project clobber via the machine-global
  personal root.** `~/.claude` / `~/.agents` hold one manifest whose
  `ProvenanceBase` (plan.md:351-361) carries no project discriminator. Complete
  reconciliation run from a second cosmonauts project silently deletes the first
  project's unchanged personal exports and overwrites same-`assetId` targets.
  Fix: add an owner discriminator (realpath of source root + project root, or a
  stable projectId), key entries by `(owner, assetId)`, restrict source-removed
  deletion to the invoking project, and classify a foreign-owned `outputPath` as
  a reported conflict.

- **M-2 (B:design-attack) — bare `sync` and bare `--check` disagree on the same rows.**
  D-002 makes bare sync request copy unconditionally while bare `--check`
  validates each asset's *recorded* mode. A `--link` opt-in therefore reads
  `current` under check (exit 0) but `source-ahead (mode)` under sync, which then
  replaces the symlink with a copy — with no conflict protection, since B-007
  guards only `locally-edited` and D-008 makes a correct link `current`. In a
  plan whose thesis is mechanical drift detection, check must be a faithful
  preview of sync. Fix: make recorded mode **sticky** (copy only for
  never-managed assets); reserve conversion for an explicit flag.

- **M-3 (B:design-attack) — no asset-selection surface, so the plan's own close
  gates are unsatisfiable.** The complete catalogue (plan.md:308) is every
  runtime-visible skill; §9's CLI exposes no `--kind`/asset narrowing, yet D-007
  presupposes "explicitly selected target/scope/kind inventory". At B-008's close
  condition ("remove backups only after `--check` passes", plan.md:185/412) the
  five stale dirs are `locally-edited` and ~41 skills are `missing`; no invocation
  can be scoped to the two commands. Fix: add `--kind`/asset narrowing, or
  redefine the complete inventory as manifest-owned ∪ explicitly requested.

- **M-4 (B:spec-fidelity + codebase-feasibility ⊕) — AC-5 clause 2 is unowned.**
  "the generated copies for at least the Claude Code target replace today's manual
  copies" is asserted by no behavior's `Expected` and evidenced by no `Test`.
  B-010's test is a unit test over supplied rows; B-012's five pairs exclude the
  bundle. The real manual copy — `~/.claude/skills/cosmonauts`, a verified
  unprovenanced plain directory in **personal** scope — is named nowhere in
  plan.md, and D-007 defaults skills to **project** scope, so default sync creates
  a *second* copy and leaves the real one to go stale the moment B-010 strips the
  authored tables. Fix: add the bundle pair to B-012's enumerated pairs and
  evidence artifact; pin the bundle's default scope in D-007.

### Medium

- **Md-1 (A:PR-003)** Recovery table omits normal post-commit crash cells
  (`target=new, manifest=new, journal=present`, with and without backup) that the
  specified write order *produces*; the fallback calls them ambiguous conflicts.
  Needs a complete manifest/target/backup/stage/journal state table.
- **Md-2 (A:PR-004)** Containment preflight runs *inside* the owner-root
  transaction, but `withEntityFileLock` `mkdir`s the lock parent and writes there
  during acquisition — so a symlinked `~/.claude` is already written through
  before the adapter can reject it. Needs a race-aware ordering/lock-location contract.
- **Md-3 (A:PR-005 ⊕ B:codebase-feasibility)** `.agents/` is **not** gitignored
  (`git check-ignore .agents` matches nothing; `.gitignore:16-18` covers
  `.claude/`, `.gemini/`, `.antigravitycli/`). D-007's omitted target selects
  claude+codex, so a bare `harness sync` leaves ~46 untracked
  `<repo>/.agents/skills/*` directories plus a manifest, while plan.md:468 says
  `.gitignore` does not change. Fix: cover every project-scope owner root the
  registry can write; assert `git status --porcelain` empty after a default sync.
- **Md-4 (A:PR-006 ⊕ B:spec-fidelity/scope-sequencing)** Parse-time vs
  selection-time behavior for `gemini-cli`/`open-code` definition blocks is
  unspecified. `tests/agent-packages/definition.test.ts:261` currently pins that
  such blocks parse; the dead-code gate deletes the local `TARGETS` table. Also
  unstated: whether the `--target` rejection message stays `"claude-cli, codex"`
  or becomes canonical. A worker would coin-flip both.
- **Md-5 (A:PR-007)** `ExportScope` currently lives in `lib/skills/exporter.ts`,
  but the adapter core references it while `lib/skills/` is supposed to depend

## Disposition

The plan is **viable and unusually well-specified** — the transaction model,
four-state classifier, and compatibility metadata are real design work, and
round-1's eleven findings were genuinely absorbed. But it is **not ready for task
creation**:

1. Three escalations (E-1..E-3) touch ratified ground; agents may not resolve them.
   With the pre-existing Gate 0 set (D-001..D-004, D-010), the human now has
   **eight** rulings pending.
2. Round-2's eight findings — including a self-deadlock and a data-destroying
   migration — were never fed back to the planner.
3. Four major defects from the independent channel need design revision, not patches.

**Recommended sequence:** human rules the eight Gate 0 items → one planner
revision round carrying this synthesis plus `review-2.md` → coordinator
re-verifies → then task creation. Hand-patching a 56KB design across ~22
interlocking findings would be exactly the "coordinator hand-designs the plan"
failure the pipeline exists to prevent.
