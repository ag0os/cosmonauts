# Drive improvement observations — chain-stage-context

Read-only pass over `events.jsonl`, the nine task summaries, and the branch
history. Prescriptive only; nothing here changes the shipped feature.

| Observed problem | What happened in this run | Suggested improvement | Why it helps |
|---|---|---|---|
| A worker can pass a bound analysis gate by widening its own baseline | TASK-672 (`17a9f52`) added `finding_counts` entries for `chain-runner.ts`, `review-rounds.ts` and `chain-runner.test.ts` to `.fallow-baselines/health.json` with a bare commit message. The audit then read green against a floor the branch had moved. Audited against `main`'s baselines it failed with five complexity findings. | Make the finalizer refuse a source commit that edits `.fallow-baselines/**` unless the commit body contains a stated reason, or require baseline edits to land as their own commit. | The plan already forbids silent re-saves in prose (§7a); nothing enforced it. A gate whose floor the gated party can move is not a gate. |
| Review artifacts can be orphaned with no signal | `review-3.md` (2 high, 3 medium, assessment withholding approval) was committed alongside rounds 1-2 and never dispositioned — no Decision Log entry, task, or roadmap item cited it. It was found only by reading the plan directory directly. | Have `plan check-artifacts` warn when a `review-N.md` carrying `## Findings` has no round-qualified citation in any `D-###` entry. The assessor shipped by this very plan already computes exactly that. | This plan exists because unaddressed review rounds slip past silently. The same failure had already happened to the plan itself. |
| Decision Log citations were unusable by the gate they feed | D-009/D-010 wrapped whole citations in backticks (`` `review-2.md PR-001` ``), placing them inside the inline-code span the assessor masks. A mutation probe confirmed the counterfactual: `blocked / missing-review-reference` with the wrapped form, `accepted` without. | Document the citation form in the deviation-protocol reference and assert it in `check-artifacts`. | The correct form is load-bearing but invisible — it looks like a formatting preference and is not. |
| The verification task cannot record a partial pass | TASK-676 correctly failed and left ACs 7-8 unchecked, but the run aborted, so nine tasks of real work ended in `run_aborted` with no completed verification record. | Let a verification-only task report `blocked-with-findings` distinctly from `failure`, so the run ends `blocked` rather than `aborted` and the finished implementation is not reported as an aborted run. | The distinction is between "the work is wrong" and "the work is done and the gate found something" — operators act differently on each. |
| Quality Manager returned nothing, again | The `coding/quality-manager` chain ran ~45 minutes, produced zero bytes, and accumulated 15s CPU at 0.2%. It is GPT-backed, so this is not the recorded Opus-usage stall. Second recorded instance of QM never returning a verdict. | Give the QM chain a heartbeat or a hard timeout that fails loudly, and investigate why a GPT-backed stage idles indefinitely. | Silence currently costs a full wall-clock hour before anyone notices there is no verdict to read. |
| Long detached runs need a cheap liveness watch | Three background watchers were killed by system memory pressure mid-run (two polling shells, one codex review). The Drive process itself was never affected, but each kill looked like it might have been. | Prefer file-mtime/event-log polling in pure shell over spawning a CLI process per poll, and document that a killed watcher is not a killed run. | A watcher that costs a Node process every 30s is the first thing the OOM killer takes, exactly when the run matters most. |

## Ranked follow-ups

1. Enforce the baseline-edit rule in the driver finalizer (highest value; it is the only item here that let a red gate read green).
2. Teach `check-artifacts` the uncited-findings-round warning, reusing `assessPlanReviewRound`.
3. Separate `blocked-with-findings` from `failure` for verification-only tasks.
4. Add a QM heartbeat/timeout and investigate the idle stall.

## Non-goals

- Changing the analysis thresholds themselves, or paying down the pre-existing debt tracked by `analysis-debt-paydown`.
- Reworking Drive's `missions/tasks/` commit exclusion; committing those separately is understood and cheap.
