# Execution probe

The coding worker alone can call `execution_probe` to check whether source sites execute under one project test command. Supply one or more tracked, project-relative regular source locations (`path`, 1-based `line`, and a `statementTemplate` containing both `{{hitFile}}` and `{{marker}}`), a `testCommand`, optional `timeoutMs`, and `confirmProjectExecution: true`. The statement must be valid at each insertion point and append its marker plus a newline to `{{hitFile}}` when reached. The tool inserts statements before their specified lines, runs the command exactly once, then restores and digest-checks the original bytes even on nonzero exit, timeout, or abort. It reports counts by location, exit status, tracked side effects, and whether a zero is usable. A zero is usable only on exit 0 with verified restoration and no other tracked-file changes. A git-dirty tracked source is eligible; changing source bytes between validation and insertion is not.

A refused command/location does not provide evidence. Destructive Git commands are refused. A `recovery-required` result names an outstanding journal instead of reporting counts; stop and arrange safe recovery. A later call can recover intact journals from verified backups before probing, but corrupt sidecars or unverifiable source changes require human recovery. Drive blocks on an outstanding journal before spawn, postflight, or commit. Do not claim an unreachable site without a recorded usable zero. Explicit confirmation authorizes running project code with worker authority; review the command before setting it to true.
