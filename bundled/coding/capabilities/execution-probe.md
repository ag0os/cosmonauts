# Execution probe

The coding worker alone can call `execution_probe` to check whether source sites execute under one project test command. Supply one or more tracked, project-relative regular source locations (`path`, 1-based `line`, and a `statementTemplate` containing both `{{hitFile}}` and `{{marker}}`), a `testCommand`, optional `timeoutMs`, and `confirmProjectExecution: true`. The statement must be valid at each insertion point and append its marker plus a newline to `{{hitFile}}` when reached. The tool inserts statements before their specified lines, runs the command exactly once, then restores and digest-checks the original bytes even on nonzero exit, timeout, or abort. The probe caps aggregate command stdout and stderr at 1,048,576 bytes; exceeding that limit terminates the process tree and reports `output-overflow`. Failed results include bounded stdout and stderr tails (2,000 bytes each). It reports counts by location, exit status, tracked side effects, and whether a zero is usable. A zero is usable only on exit 0 with verified restoration and no other tracked-file changes. A git-dirty tracked source is eligible; changing source bytes between validation and insertion is not.

A refused command/location does not provide evidence. Destructive Git commands are refused. A `recovery-required` result names an outstanding journal instead of reporting counts; stop and arrange safe recovery. A later call can recover intact journals from verified backups before probing, except when a `termination-error` marker exists. That marker means the tool could not verify that the test command's process tree stopped; without durable process identity, the command may still be running. Stop and manually confirm that no process of the test command is alive. Verify every instrumented file is restored from its digest-verified sidecar (including its index entry), then remove the `termination-error` marker and journal. Corrupt sidecars or unverifiable source changes require human recovery; do not simply delete their journal. Drive blocks on an outstanding journal before spawn, postflight, or commit. Do not claim an unreachable site without a recorded usable zero. Explicit confirmation authorizes running project code with worker authority; review the command before setting it to true.
