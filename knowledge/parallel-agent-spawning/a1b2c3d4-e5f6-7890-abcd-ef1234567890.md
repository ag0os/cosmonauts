spawn_agent is non-blocking: it returns { status: 'accepted', spawnId } immediately, and the child session runs as a background Promise. This enables parallelism — coordinators call spawn_agent N times and all N children run concurrently. Blocking spawn was rejected because it would serialize all child work, preventing a coordinator from dispatching a full wave of tasks at once. The non-blocking pattern is adapted from OpenClaw's sessions_spawn, where LLMs were shown to handle 'accepted' returns correctly when the prompt contract is clear.
